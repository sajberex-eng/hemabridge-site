# Как обновляется сайт https://bridge.hemcenter.kz/

Сайт лежит на сервере Центра гематологии (Apache, Ubuntu) и обновляется **сам** из GitHub: `sajberex-eng/hemabridge-site`, ветка `hemabridge-redesign`.

## Как это устроено

На сервере каждые 2 минуты по cron запускается скрипт выкладки. Он:

1. забирает с GitHub ветку `hemabridge-redesign` в свою копию репозитория на сервере;
2. если с прошлого раза появился новый коммит, копирует в папку сайта публичные файлы: `index.html`, `i18n/`, `img/`, `docs/`, `robots.txt`, `.htaccess`. Исходники (`src/`, `tools/`, `.git`, `*.md`, `*.py`) на сайт не попадают;
3. записывает коммит в журнал выкладок.

Адрес сервера, логин, путь к скрипту и папке сайта в репозиторий не записываются (он публичный). Они хранятся только локально, в `CLAUDE.local.md` (исключён из git), а доступ по SSH — только по ключу.

## Каждый раз после правок

1. На компьютере: пересобрать (`cd src; python build.py`), поднять версию в `src/build.py`, закоммитить и отправить в ветку `hemabridge-redesign` (`git push`).
2. Подождать около 2 минут.
3. Открыть https://bridge.hemcenter.kz/ и проверить подпись внизу страницы: «версия …» (атрибут `data-v`) должна совпадать с той, что в `src/build.py`. Браузер может показывать старую копию из кэша, тогда обновить страницу с Ctrl+F5.

Больше ничего делать не нужно: заходить на сервер для обычной выкладки не требуется.

## Если сайт не обновился

Зайти на сервер по SSH (ключом) и посмотреть журнал выкладок, затем запустить скрипт вручную с ключом `--force` от имени пользователя, которому принадлежат файлы сайта (`sudo -u <владелец> <скрипт> --force`). Точные пути — в `CLAUDE.local.md`.

## Откат

Проще всего откатить коммит в git (`git revert`) и отправить его: через 2 минуты на сайте будет предыдущая версия.

Перед изменением настроек выкладки 2026-11-19 на сервере сохранена копия скрипта и папки сайта (путь — в `CLAUDE.local.md`). Восстановить папку сайта из такого архива: `sudo tar -xzf <архив>.tar.gz -C <папка сайта>`.

## Важно

- Скрипт только добавляет и заменяет файлы, но не удаляет с сайта то, что удалено из репозитория. Удалённый из проекта файл нужно убрать с сервера вручную.
- Сайт закрыт от поисковиков (`noindex` + `robots.txt`) до официального запуска. Для запуска убрать `noindex` в `src/build.py` и `Disallow` в `robots.txt`.
- Формы демонстрационные. Реальные данные пациентов можно принимать только на серверах в Казахстане.
