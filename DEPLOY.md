# Как обновляется сайт https://bridge.hemcenter.kz/

Сайт лежит на сервере Центра гематологии (Apache, Ubuntu) и обновляется **сам** из GitHub: `sajberex-eng/hemabridge-site`, ветка `hemabridge-redesign`.

## Как это устроено

На сервере каждые 15 минут по cron запускается скрипт выкладки (до 25.11.2026 — каждые 2 минуты). Он:

1. забирает с GitHub ветку `hemabridge-redesign` в свою копию репозитория на сервере;
2. если с прошлого раза появился новый коммит, копирует в папку сайта публичные файлы:
   - если в корне репозитория есть **`public.txt`**, копируются только перечисленные в нём пути (по одному на строку, папки со слешем в конце: `img/`, `car-t/`). Файл пишет сборка; пустые строки и строки с `#` пропускаются. Если в списке путь, которого нет в репозитории, абсолютный путь или `..`, выкладка не выполняется, а в журнал пишется ошибка;
   - если `public.txt` нет, копируется весь репозиторий, кроме служебного;
   - в обоих режимах исходники и служебные файлы (`src/`, `tools/`, `.git`, `.claude/`, `*.md`, `*.py`, сам `public.txt`) на сайт не попадают;
3. записывает коммит и режим (`[public.txt]` или `[all]`) в журнал выкладок.

Адрес сервера, логин, путь к скрипту и папке сайта в репозиторий не записываются (он публичный). Они хранятся только локально, в `CLAUDE.local.md` (исключён из git), а доступ по SSH — только по ключу.

## Каждый раз после правок

1. На компьютере: пересобрать (`cd src; python build.py`), поднять версию в `src/build.py`, закоммитить и отправить в ветку `hemabridge-redesign` (`git push`).
2. Подождать до 15 минут. Если нужно срочно, запустить скрипт на сервере вручную (см. «Если сайт не обновился»).
3. Открыть https://bridge.hemcenter.kz/ и проверить подпись внизу страницы: «версия …» (атрибут `data-v`) должна совпадать с той, что в `src/build.py`. Браузер может показывать старую копию из кэша, тогда обновить страницу с Ctrl+F5.

Больше ничего делать не нужно: заходить на сервер для обычной выкладки не требуется.

## Если сайт не обновился

Зайти на сервер по SSH (ключом) и посмотреть журнал выкладок, затем запустить скрипт вручную с ключом `--force` от имени пользователя, которому принадлежат файлы сайта (`sudo -u <владелец> <скрипт> --force`). Точные пути — в `CLAUDE.local.md`.

## Откат

Проще всего откатить коммит в git (`git revert`) и отправить его: в течение 15 минут на сайте будет предыдущая версия.

Перед изменением настроек выкладки 2026-11-19 на сервере сохранена копия скрипта и папки сайта, перед переходом на `public.txt` 2026-11-20 — копия скрипта (пути — в `CLAUDE.local.md`). Восстановить папку сайта из такого архива: `sudo tar -xzf <архив>.tar.gz -C <папка сайта>`.

## Важно

- Скрипт только добавляет и заменяет файлы, но не удаляет с сайта то, что удалено из репозитория или из `public.txt`. Удалённый из проекта файл или раздел нужно убрать с сервера вручную.
- Сайт закрыт от поисковиков (`noindex` + `robots.txt`) до официального запуска. Для запуска убрать `noindex` в `src/build.py` и `Disallow` в `robots.txt`.
- Формы демонстрационные. Реальные данные пациентов можно принимать только на серверах в Казахстане.
